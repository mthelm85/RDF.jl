    RDF Terms#

    RDF data is built from three kinds of terms. All three are subtypes of RDFTerm.

    RDF.RDFTerm

    source 
    RDFTerm

    Abstract supertype for all RDF terms: IRI, BlankNode, Literal, and TripleTerm.

    Type hierarchy#

    RDFTerm
├── IRI
├── BlankNode
├── Literal
└── TripleTerm   (RDF-star — embedded triples in subject or object position)

    IRI#

    An absolute IRI (RFC 3987). IRIs identify resources and are used as subjects, predicates, and objects.

    RDF.IRI

    source 
    IRI(s::AbstractString) <: RDFTerm

    An absolute IRI (RFC 3987). Must begin with a scheme (e.g. http:) and contain no unencoded spaces. Use the iri"" string macro for compile-time validation.

    IRI("http://example.org/Alice")
iri"http://schema.org/Person"

    RDF.@iri_str

    source 
    iri"http://example.org/foo"

    String macro that constructs an IRI and validates the value at compile time. Equivalent to IRI(s) but catches invalid IRIs before the program runs.

    Construction#

    IRI("http://example.org/Alice")    # runtime validation
iri"http://schema.org/Person"      # compile-time validation

    Validation rules: must begin with a scheme (http:, urn:, etc.) and must not contain unencoded spaces. IRIs are interned globally — two IRI values with the same string are ===.

    BlankNode#

    A blank node represents an unnamed resource local to a graph. Blank nodes should be created via blank! to guarantee unique identifiers.

    RDF.BlankNode

    source 
    BlankNode <: RDFTerm

    An RDF blank node identified by an opaque UInt64 id. Blank nodes should be created via blank! rather than constructed directly, to ensure ids are unique within the graph.

    RDF.blank!

    source 
    blank!(g::Graph) -> BlankNode
blank!(g::Graph, n::Int) -> Vector{BlankNode}

    Mint one or more fresh blank nodes registered to graph g.

    g  = Graph()
b1 = blank!(g)         # mint one blank node belonging to g
b2, b3 = blank!(g, 2)  # mint two at once

    Literal#

    A typed value with a lexical form, datatype IRI, and optional language tag.

    RDF.Literal

    source 
    Literal <: RDFTerm

    An RDF literal with a lexical form, datatype IRI, and optional language tag.

    Common constructors:

    • Literal("hello") — plain string (xsd:string)

    • Literal("hello"; lang="en") — language-tagged string (rdf:langString)

    • Literal("hello"; lang="ar", dir="rtl") — directional string (rdf:dirLangString, RDF 1.2)

    • Literal("hello", IRI("...")) — explicit datatype

    • Literal(42) → xsd:integer, Literal(3.14) → xsd:double, Literal(true) → xsd:boolean

    • Literal(Date(2024,1,1)) → xsd:date

    Common constructors#

    Expression Datatype
    Literal("hello") xsd:string
    Literal("hello"; lang="en") rdf:langString
    Literal("hello"; lang="ar", dir="rtl") rdf:dirLangString (RDF 1.2)
    Literal("hello", IRI("...")) explicit datatype
    Literal(42) xsd:integer
    Literal(3.14) xsd:double
    Literal(true) xsd:boolean
    Literal(Date(2024,1,1)) xsd:date
    Literal(DateTime(2024,1,1,12,0,0)) xsd:dateTime

    Coercing a literal to a Julia value#

    RDF.value

    source 
    value(lit::Literal)
value(T::Type, lit::Literal)

    Parse the lexical form of lit to a Julia value.

    The one-argument form infers the target type from the datatype IRI:

    XSD / RDF datatype Julia type
    xsd:string, rdf:langString, rdf:dirLangString String
    xsd:boolean Bool
    xsd:integer and all integer subtypes Int64 (or BigInt if too large)
    xsd:double Float64
    xsd:float Float32
    xsd:decimal BigFloat (finite-precision approximation)
    xsd:date Dates.Date
    xsd:dateTime, xsd:dateTimeStamp Dates.DateTime (timezone stripped)

    The two-argument form additionally converts the result to T using Julia's convert. This means numeric widening works naturally:

    value(Literal(42))              # => 42  (Int64)
value(Int64,   Literal(42))     # => 42
value(Float64, Literal(42))     # => 42.0   (Int64 → Float64 via convert)
value(Int64,   Literal(3.14))   # throws LiteralValueError (inexact)

    Throws LiteralValueError if the lexical form cannot be parsed or if the resulting value cannot be converted to T. See tryvalue for a non-throwing variant.

    RDF.tryvalue

    source 
    tryvalue(lit::Literal)
tryvalue(T::Type, lit::Literal)

    Like value but returns nothing instead of throwing on failure.

    tryvalue(Literal(42))               # => 42
tryvalue(Float64, Literal(42))      # => 42.0
tryvalue(Int64,   Literal(3.14))    # => nothing  (inexact)
tryvalue(Int64,   Literal("oops", xsd.integer))  # => nothing
    lit = Literal(42)

# One-argument: infer Julia type from the RDF datatype
value(lit)              # => 42  (Int64, because xsd:integer)

# Two-argument: convert to a requested type
value(Int64,   lit)     # => 42
value(Float64, lit)     # => 42.0   (Int64 → Float64 via convert)
value(Int64,   Literal(3.14))   # throws LiteralValueError (inexact)

# Safe variant — returns nothing instead of throwing
tryvalue(lit)                          # => 42
tryvalue(Float64, lit)                 # => 42.0
tryvalue(Int64,   Literal(3.14))       # => nothing
tryvalue(Int64,   Literal("oops", xsd.integer))  # => nothing

    The natural Julia type for each RDF datatype:

    RDF datatype Julia type
    xsd:string, rdf:langString String
    xsd:boolean Bool
    xsd:integer and all integer subtypes Int64 (or BigInt if too large)
    xsd:double Float64
    xsd:float Float32
    xsd:decimal BigFloat (finite-precision approximation)
    xsd:date Dates.Date
    xsd:dateTime, xsd:dateTimeStamp Dates.DateTime (timezone stripped)

    The two-argument value(T, lit) uses Julia's convert, so any numeric widening that convert supports works (e.g. Int64 → Float64, Float32 → Float64). Abstract supertypes like Number or AbstractFloat work too.

    TripleTerm#

    TripleTerm (RDF-star) allows an embedded triple to appear in both subject and object positions, enabling statement-level annotations without blank-node reification.

    RDF.TripleTerm

    source 
    TripleTerm(subject, predicate, object) <: RDFTerm

    An RDF-star triple term — an embedded triple used as an RDF term in either subject or object position. Enables statement-level annotations (e.g. via rdf:reifies) without blank-node reification.

    The subject may be an IRI, BlankNode, or nested TripleTerm; the predicate must be an IRI; the object may be any ObjectTerm.

    tt = TripleTerm(iri"http://example.org/bob", rdf.type, iri"http://example.org/Person")

# As object (most common — rdf:reifies annotation)
push!(g, Triple(iri"http://example.org/claim", rdf.reifies, tt))

# As subject
push!(g, Triple(tt, iri"http://example.org/certainty", Literal(0.9)))
    tt = TripleTerm(ex.alice, ex.age, Literal(30))
push!(g, Triple(ex.claim, rdf.reifies, tt))

    Triple and Quad#

    A Triple has three fields: subject::SubjectTerm, predicate::IRI, object::ObjectTerm. See Triple in the Graphs & Datasets page for the full API.

    A Quad is a named-graph extension — (subject, predicate, object, graph) — used when iterating Dataset quads.

    Alias Allowed types

    PredicateTerm IRI
    ObjectTerm IRI, BlankNode, Literal, TripleTerm

    source

    Union type for valid RDF subject positions: IRI, BlankNode, or TripleTerm (RDF-star embedded triple).

    RDF.PredicateTerm

    source 
    PredicateTerm

    Alias for IRI; only IRIs are valid in the predicate position.

    RDF.ObjectTerm

    source 
    ObjectTerm

    Union type for valid RDF object positions: IRI, BlankNode, Literal, or TripleTerm.

    RDF.GraphName

    source 
    GraphName

    Union type for RDF graph names: IRI or BlankNode.

    Namespace helper#

    Namespace provides a convenient shorthand for constructing IRIs within a common prefix.

    RDF.Namespace

    source 
    Namespace(base::String)

    A namespace prefix for constructing IRIs using dot notation or bracket indexing.

    ex  = Namespace("http://example.org/")
ex.Alice          # => IRI("http://example.org/Alice")
ex["first-name"]  # => IRI("http://example.org/first-name")
    ex   = Namespace("http://example.org/")
foaf = Namespace("http://xmlns.com/foaf/0.1/")

ex.alice            # => IRI("http://example.org/alice")
foaf.name           # => IRI("http://xmlns.com/foaf/0.1/name")
ex["with spaces"]   # => IRI("http://example.org/with%20spaces")

    Built-in vocabulary modules#

    Prefix modules expose every term from common namespaces as named constants:

    rdf.type          # IRI("http://www.w3.org/1999/02/22-rdf-syntax-ns#type")
rdfs.subClassOf   # IRI("http://www.w3.org/2000/01/rdf-schema#subClassOf")
xsd.integer       # IRI("http://www.w3.org/2001/XMLSchema#integer")
owl.sameAs        # IRI("http://www.w3.org/2002/07/owl#sameAs")
skos.prefLabel    # IRI("http://www.w3.org/2004/02/skos/core#prefLabel")
dc.title          # IRI("http://purl.org/dc/elements/1.1/title")
dcterms.creator   # IRI("http://purl.org/dc/terms/creator")
foaf.name         # IRI("http://xmlns.com/foaf/0.1/name")
schema.Person     # IRI("https://schema.org/Person")

    Available modules: rdf, rdfs, xsd, owl, skos, dc, dcterms, foaf, schema.
